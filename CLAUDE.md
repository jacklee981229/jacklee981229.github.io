# CLAUDE.md: Jack's Space

Jack's personal blog: a static Astro site on GitHub Pages that replaces the old Hexo site at https://jacklee981229.github.io. These rules add to `C:\repos\Jack\CLAUDE.md`. The plans are in `docs/plan/todo/` (still open) and `docs/plan/done/` (finished), one file each with its decisions and tasks at the end, as the root CLAUDE.md says. The site's own rebuild, with its scope, stack and first decisions, is [site-v2.md](docs/plan/done/site-v2.md).

## Commands

Run these in this folder.

- `npm install`: install packages (first time, or after `package.json` changes).
- `npm run dev`: local site with live reload at http://localhost:4321. Shows drafts; the palette finds no posts here (everything else in it works).
- `npm run build`: build the site into `dist/`, check the sitemap against the built pages (a mismatch stops it), then build the search index.
- `npm run preview`: serve the built `dist/` at http://localhost:4321, search included.
- `npm run check`: type-check the project.
- `npm test`: unit tests for the logic in `src/lib/`.
- `npm run new "Title" topic`: start a draft post.

Package versions are pinned to ones that run on Node 20.18 (D1 in [site-v2.md](docs/plan/done/site-v2.md)), including the `@astrojs/language-server` override in `package.json`, which keeps `npm run check` working. Don't upgrade them without asking, and ignore Astro's "new version available" message: the new versions need Node 22 or newer.

- Travel Map (`/travel/`, `src/pages/travel.astro`): the places Jack has been, coloured on a globe (what the page opens on) or on a flat map of the world. The list is `src/content/travel/visited.yaml` (its top lines say how to write it); the first place is home. `src/lib/travel/places.js` turns the listed names into the map's own, everyday names included (`ALSO`), and stops the build on one it doesn't know; `src/lib/travel/map.js` draws the flat map while the site is built and gives each place its step along the colours (`colourSteps`: home first, then by distance from it); `src/lib/travel/globe.js` draws the globe in the browser (a drag, a flick or the arrow keys turn it). Both are tested by `tests/travel.test.js`, apart from the globe's drawing. The colours run from `--visited-near` to `--visited-far` in `tokens.css`; the page's styles mix each place's colour from its step, and the globe takes each country's colour from its shape on the flat map, so the two can't differ. On the flat map each visited country is a small picture of its own laid over the map (the faint mark it leaves, a blurred copy that glows, the country, a shape that stays put for the mouse to be checked against, and its name tag); on the globe they are canvases laid over the one with the lines, two for the places at rest and two for a risen one. The breathing is a CSS animation of those layers, gentle at rest and stronger for a risen place, so nothing is redrawn for it. A place under the mouse (or tapped) rises: a little bigger (`--lift-scale`), thin lines across it, a brighter edge, its name over it in capitals; the globe holds still meanwhile. The pointer over the globe stays the ordinary arrow. Choosing Flat opens the globe out into the flat map, and Globe closes it up again: `openingOut` and `inView` in `map.js` are the maths (each point part of the way from its place on the globe to its place on the flat map, the far side kept out of sight until it no longer folds over the near side), `globe.js` draws it on its canvases, which reach as far as the flat map, and at the flat end they hand over to the flat map's own picture. The globe and the flat map share one spot on the page; `data-off` marks the one that's out of sight. The shapes are Natural Earth's, from the `world-atlas` package: the coarse file is what's drawn; the finer one also knows the places too small to draw (Singapore), which are only named under the map.

## UI checks

Every task that changes the UI passes these in the sweep: after Jack confirms the feature and before it's committed (`C:\repos\Jack\CLAUDE.md`, "Verify before you report"):

- It works at 375 px and 1280 px wide, in both light and dark mode.
- Keyboard only: everything clickable shows a visible focus, and the tab order follows the page.
- Text contrast is at least 4.5:1 (3:1 for large text), measured rather than guessed.
- `prefers-reduced-motion` is respected, and nothing scrolls sideways.
- Images have their size set, so nothing jumps while the page loads.

## Design rules

- [docs/design-ideas.md](docs/design-ideas.md) is an idea bank from two reference blogs. Read it only when Jack asks for design ideas or inspiration; it's not a rulebook for every UI change. When it is used, suggest ideas by their ID and record what's adopted or rejected in its Decisions section.

- Colours, fonts, spacing and radii come only from the design tokens. Components contain no raw colour values.
- No full-page loaders, except the welcome screen as the feature table in [site-v2.md](docs/plan/done/site-v2.md) describes it. No third-party scripts except the ones the plans name.
- Scripts and styles go through Astro's build (import them from `src/`), never `public/`. Built files get a fingerprint in their names that changes when they do; files in `public/` keep their names, and GitHub Pages lets browsers reuse a saved copy for up to 10 minutes, so right after a deploy a visitor would get the new page with the old script until a hard refresh.
